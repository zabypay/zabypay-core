# Paying a ZabyPay Payment Request

This doc shows you how to **render a QR** for a customer and how to **pay
one** without writing a frontend.

ZabyPay returns a standards-compliant payment URI for every payment request
(`qr_data.payment_uri` in the API response). The URI follows:

| Network | URI scheme | Example |
|---|---|---|
| Ethereum | EIP-681 | `ethereum:0xabc…@1?value=10000000000000000` |
| BNB Smart Chain | EIP-681 (`@56`) | `ethereum:0xabc…@56?value=…` |
| Solana | Solana Pay | `solana:GfYa…?amount=0.05&reference=…` |

Any modern wallet (MetaMask, Trust Wallet, Coinbase Wallet, Rainbow, Phantom
for Solana) parses these natively — when the customer scans or opens the
URI, the wallet pre-fills the recipient, amount and chain.

---

## 1. Get a payment URI

Create a payment request first (full reference in [API.md §5.1](API.md)):

```bash
curl -X POST http://localhost:8080/api/v1/payments/payment-requests \
  -H "X-API-Key: $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"amount":"0.01","currency":"eth","external_id":"order-1001"}'
```

In the response, grab `qr_data.payment_uri`:

```bash
URI=$(curl -s -X POST http://localhost:8080/api/v1/payments/payment-requests \
  -H "X-API-Key: $API_KEY" -H "Content-Type: application/json" \
  -d '{"amount":"0.01","currency":"eth","external_id":"order-1002"}' \
  | jq -r '.qr_data.payment_uri')
echo "$URI"
# ethereum:0xafc9177d4455ba0788c45f1bca94e2ddd248ab08@1?value=10000000000000000
```

> **zsh users:** always wrap the URI in **single quotes** (or assign it to a
> variable and pass it as `"$URI"`). The `?` in the URI is a glob pattern
> in zsh and you'll get
> `zsh: no matches found: ethereum:...` if you paste it bare.

## 2. Render the QR

### Option A — `qrencode` CLI (recommended)

#### Install

| OS | Command |
|---|---|
| macOS (Homebrew) | `brew install qrencode` |
| Ubuntu / Debian | `sudo apt-get update && sudo apt-get install -y qrencode` |


Verify:
```bash
which qrencode      # macOS / Linux
qrencode --version  # both
```

#### Print to terminal (zero files)
```bash
echo "$URI" | qrencode -t ansiutf8           # color
echo "$URI" | qrencode -t utf8               # plain
echo "$URI" | qrencode -t ansiutf8 -m 2      # tighter margin
```
Scan the terminal output with your phone wallet's camera.

#### Write a PNG you can view / send
```bash
qrencode -o ~/payment.png -s 10 "$URI"
ls -la ~/payment.png
open ~/payment.png       # macOS  (Preview)
xdg-open ~/payment.png   # Linux
```
- `-s 10` makes each QR module 10 pixels wide → ~330×330 px image. Bump to
  `-s 16` if you'll print it on paper.
- `-l H` adds the highest error-correction level (recommended if you'll
  overlay a logo or print at small size).

#### SVG (scales without pixelation)
```bash
qrencode -t SVG -o ~/payment.svg "$URI"
```

### Option B — Browser, no install

```bash
URL="https://api.qrserver.com/v1/create-qr-code/?size=400x400&data=$(python3 -c "import urllib.parse,sys;print(urllib.parse.quote(sys.argv[1]))" "$URI")"
echo "$URL"
open "$URL"          # macOS
xdg-open "$URL"      # Linux
```
A 400×400 PNG opens in your default browser. Scan with your phone.

> The image is generated by a third-party service. Don't use this in
> production for sensitive amounts — install `qrencode` instead.

### Option C — In a Rust backend (no CLI)

Add to `Cargo.toml`:
```toml
qrcode = "0.14"
image  = "0.25"
```

```rust
use qrcode::QrCode;
use image::Luma;

let code = QrCode::new(payment_uri.as_bytes())?;
let img  = code.render::<Luma<u8>>().min_dimensions(400, 400).build();
img.save("payment.png")?;
```

### Option D — In a JavaScript frontend
```bash
npm i qrcode
```
```js
import QRCode from "qrcode";
const dataUrl = await QRCode.toDataURL(paymentUri, { width: 400 });
document.getElementById("qr").src = dataUrl;
```

## 3. Pay it (no QR needed either)

The same URI can be **pasted directly** into any wallet's "Send" screen:

| Wallet | What to do |
|---|---|
| **MetaMask** (browser / mobile) | Open the wallet → tap **Send** → paste the URI in the recipient field. The recipient address, amount, and network are auto-filled. |
| **Trust Wallet** | Tap the QR icon → **Scan** the QR, *or* paste the URI in **Send → Address**. |
| **Coinbase Wallet** | Same — paste in the address field. |
| **Phantom** (Solana) | Use **Pay** and scan the Solana Pay QR. |
| **Hardware wallets** | Most desktop apps (Ledger Live, Trezor Suite) accept the recipient + amount fields directly; copy them out of `qr_data` (`address`, `amount`, `network_config.chain_id`). |

Quick clipboard helper:
```bash
echo -n "$URI" | pbcopy        # macOS
echo -n "$URI" | xclip         # Linux (X11, requires xclip)
echo -n "$URI" | wl-copy       # Linux (Wayland, requires wl-clipboard)
```
Then `Cmd+V` / `Ctrl+V` into the wallet.

## 4. Watch the payment confirm

After the customer broadcasts the tx, the gateway's on-chain monitor will
flip the payment to `paid` once enough confirmations land.

```bash
PAYMENT_ID=<the id you got from create>

# public read — no auth, what your customer page would call
curl -s http://localhost:8080/api/v1/public/payments/$PAYMENT_ID | jq '{status, paid_at}'

# polled with API key for the full payload
watch -n 5 "curl -s -H 'X-API-Key: $API_KEY' \
  http://localhost:8080/api/v1/payments/payment-requests/$PAYMENT_ID | jq '{status,paid_at}'"
```

Force a re-check (skip the scheduler):
```bash
curl -X GET http://localhost:8080/api/v1/verify/payment/$PAYMENT_ID \
  -H "X-API-Key: $API_KEY"
```

If you've configured a `webhook_url` on the merchant, you'll also receive a
signed `payment.paid` webhook (see [API.md §5.3](API.md#53-webhooks-emitted-server--merchant-webhook_url)).

---

## 5. Confirmation depth per network

| Network | Default confirmations before `paid` |
|---|---|
| Ethereum (`eth`) | 12 |
| BNB Smart Chain (`bnb`) | 15 |
| Solana (`sol`) | finalized (~32 slots) |

(With ETH at ~12 s/block, expect roughly 2–3 min for a confirmed payment;
BNB ~45 s; Solana usually under 15 s.)

---

## 6. Tips

- **Always quote the URI in zsh** — `?` triggers glob matching otherwise.
- **EIP-681 amounts are in wei (ETH/BNB)** — `0.01 ETH` = `10000000000000000`
  in the URI's `value=` parameter. The gateway already does this conversion;
  use the URI as-is.
- **Use testnet for development.** Issue an API key with
  `"environment_type":"testnet"` (see [API.md §4.1](API.md#41-post-apiv1merchantmerchantsmerchant_idapi-keys)).
  Mainnet payments require real funds.
- **One QR per request.** A new payment request always returns a new
  receiving address — don't reuse a QR across orders.
